# 自定义网站抓取指南

“自定义抓取”功能用于把任意代理网站接入代理池：你只需描述**如何请求该网站的页面**（URL 模板、请求头、请求体、分页方式），以及**如何从响应中提取代理**（正则分组），系统就会按模板抓取、解析并导入代理，全程可在 Web UI 中管理和运行。

- 入口：Web UI 左侧菜单 → **自定义抓取**
- 相关代码：`internal/proxypool/custom_scraper.go`（核心逻辑）、`internal/proxypool/web.go`（API）
- API 前缀：`/api/custom-scrapers`（需登录会话）

## 快速上手：5 分钟接入一个新网站

以一个虚构的代理列表站 `https://example.com/list?per_page=100&page=1` 为例（返回 HTML，每页是一张 `IP:端口` 表格）：

1. 进入“自定义抓取”页，点击 **新建**，填写：
   - **名称**：`example.com`
   - **URL 模板**：`https://example.com/list?per_page={size}&page={page}`
   - **默认协议标签**：勾选 `HTTP`（页面只有 IP:端口，无法确定协议时）
2. 切到“分页策略”页签，如果整站就一页，保持默认（固定范围 1-1）即可。
3. 点击 **测试提取**，系统会实际请求第一页并显示：
   - 实际请求的 URL 列表
   - 提取到的前 20 个匹配代理
4. 匹配正常后点击 **保存模板**，再点击 **运行抓取**。
5. 运行结束后到“代理池”页查看导入结果，到“免费代理采集”页的“采集源质量统计”查看该来源的导入/重复/失败统计。

> 提示：不想从零开始时，点击 **载入示例** 按钮可以填入内置的 `proxy.scdn.io` 示例模板，在其基础上修改。

## 模板字段详解

模板配置分布在五个页签中，与字段一一对应。

### 基础配置

| 字段 | 说明 |
| --- | --- |
| 模板 ID | 已保存模板的数据库 ID，只读；新建时为空 |
| 名称 | 用于在模板列表中识别来源站点或规则用途 |
| URL 模板 | 抓取地址，支持 `{page}`、`{size}` 占位符 |
| 启用 | 仅启用的模板会参与定时采集；手动运行不受影响 |
| 默认协议标签 | `http` / `https` / `socks5` 可多选，见[下文](#默认协议标签多协议展开) |
| 备注 | 自由填写，如记录该站的登录要求、抓取频率限制等 |

`{page}` 会被替换为当前页码，`{size}` 会被替换为“每页数量”。若“每页数量”留空，`{size}` 替换为空字符串——适用于 URL 中没有每页数量参数的站点。

### 分页策略

| 字段 | 说明 |
| --- | --- |
| 页码模式 | `固定范围` 或 `全部页自动识别`，见[下文](#分页策略固定范围-vs-全部页自动识别) |
| 起始页 / 结束页 | 固定范围模式下的抓取区间 |
| 每页数量 | 替换 URL/请求体中的 `{size}`，留空则替换为空 |
| 最多页数 | 自动识别模式的安全上限，默认 50，上限 100 |
| 并发页数 | 同时抓取的页面数量（1-50），见[请求设置](#请求设置方法超时并发重试与出口) |
| 失败重试次数 | 单页请求失败后的额外重试次数（0-10） |
| 失败自动停止 | 页面请求失败累计达到该值后停止剩余页面，`0` 表示不自动停止 |
| 页数识别正则 / 分组 | 自动识别模式下解析最大页码的规则 |

### 提取规则

| 字段 | 说明 |
| --- | --- |
| 提取正则 | 从响应文本（HTML 或 JSON 文本）中匹配代理的核心正则，详见[下文](#提取正则与分组) |
| scheme/host/port/user/password 分组 | 正则中对应字段使用的捕获分组名或编号 |

### 请求设置

| 字段 | 说明 |
| --- | --- |
| 请求方法 | `GET` 或 `POST` |
| 请求超时秒数 | 单个页面请求的超时；`0` 表示使用全局请求超时（设置页中的“请求超时”） |
| 抓取出口 | `本机直连` / `通过当前代理池` / `通过指定代理` |
| 指定代理 | 出口选“通过指定代理”时填写，例如 `socks5://user:pass@host:port` |
| 导入后立即验证 | 勾选后导入的同时逐个检测代理可用性；离线导入或大批量导入时建议关闭 |
| 请求头 | 每行一个，`Header: value` 或 `Header=value`；`#` 开头的行是注释 |
| 请求体 | 仅 POST 有意义；支持 `{page}`、`{size}` 占位符 |

### 运行结果

显示抓取任务的实时过程日志与最终统计，包括自动分页识别、每个页面的请求状态/响应大小/响应预览、提取到的候选数、导入/重复/验证/失败统计。任务运行中可点击 **停止当前任务** 中止。

## 分页策略：固定范围 vs 全部页自动识别

### 固定范围（默认）

直接抓取 `[起始页, 结束页]` 区间内的每一页，不做额外探测。适合明确知道页数或只需要前几页的场景。

- URL/请求体中含 `{page}` 占位符时按页逐个生成请求；不含 `{page}` 时只生成一个请求（如单页 API）。

### 全部页自动识别（auto）

1. 先抓取起始页（第 1 次请求），其响应同时用于页数识别，不会重复请求。
2. 从起始页响应中解析最大页码，解析规则按优先级：
   - 你填写的 **页数识别正则**（配合“页数识别分组”）；
   - 未填写时，依次尝试内置规则：`?page=N` / `/page/N` / `page=或page/N` / 中文分页文案 `第 N 页`。
3. 识别出的页数超过 `最多页数` 限制时会被截断到 `起始页 + 最多页数 - 1`，防止目标站分页异常导致无限抓取。
4. 之后所有页面进入工作池按“并发页数”并发抓取。

> 建议给自动识别模式配置 `失败自动停止 ≥ 1`，这样目标站返回异常（如翻到不存在的页码）时能及时止损。

## 提取正则与分组

系统用 Go 的 `regexp` 语法（[RE2](https://github.com/google/re2/wiki/Syntax)）从响应文本中提取代理。响应即使是 JSON，也按纯文本处理——通用正则同样能从 JSON 字符串里抓出 `host:port`。

### 默认正则

不填“提取正则”时使用内置默认值：

```regex
(?:(?P<scheme>https?|socks5)://)?(?:(?P<user>[^:@\s/]+)(?::(?P<password>[^@\s/]*))?@)?(?P<host>(?:\d{1,3}\.){3}\d{1,3}|[A-Za-z0-9.-]+)\s*[:：]\s*(?P<port>\d{2,5})
```

它能够匹配以下形态：

- `1.2.3.4:8080`（裸 host:port）
- `socks5://1.2.3.4:1080`（带协议）
- `user:pass@1.2.3.4:8080`（带账号）
- `socks5://user:pass@proxy.example.com:1080`（协议 + 域名 + 账号）
- 全角冒号 `1.2.3.4：8080` 也能匹配

`host` 和 `port` 分组是必需的（两者任一为空则该匹配被丢弃）；`scheme`、`user`、`password` 分组可选。

### 自定义正则示例

**例 1：从 HTML 表格里提取**（每行是 `<td>1.2.3.4</td><td>8080</td>`）：

```regex
<td>(?P<host>\d{1,3}(?:\.\d{1,3}){3})</td>\s*<td>(?P<port>\d{2,5})</td>
```

**例 2：从 JSON 数组里提取**（响应形如 `{"data":[{"ip":"1.2.3.4","port":8080}]}`）：

```regex
"ip"\s*:\s*"(?P<host>[^"]+)"[^}]*?"port"\s*:\s*(?P<port>\d+)
```

**例 3：CSV 格式**（每行 `http,1.2.3.4,8080,user,pass`）：

```regex
(?P<scheme>https?|socks5),(?P<host>[^,\s]+),(?P<port>\d{2,5})(?:,(?P<user>[^,]*),(?P<password>[^,\s]*))?
```

### 分组名与编号

“分组”字段填**命名分组的名字**（如 `host`）或**数字编号**（如 `1`，表示第 1 个捕获组）。分组字段留空时使用默认名：`scheme`、`host`、`port`、`user`、`password`。

- scheme 分组没有匹配到内容时，使用“默认协议标签”。
- Go 正则不支持负向先行断言（`(?!...)`）和回溯，遇到复杂场景请改写为多分支或分段提取。

### 分组与多协议展开的先后关系

每条正则匹配会先解析出 `scheme/host/port/user/password` 五元组，随后进入[多协议展开](#默认协议标签多协议展开)逻辑决定最终生成几条代理记录。

## 默认协议标签：多协议展开

很多代理网站只给 `IP:端口`，不说明协议。此时（scheme 分组为空）按“默认协议标签”展开：

- 只勾选 `HTTP`：生成 1 条 `http` 代理。
- 勾选 `HTTP + SOCKS5`：生成 `http` 和 `socks5` 两条候选记录，后续健康检测会分别验证，同一 endpoint 最终合并显示协议能力标签。
- 旧配置里的 `auto` / `all` 仍兼容，等价于全选 `http,https,socks5`。

如果匹配内容本身带协议前缀（如 `socks5://1.2.3.4:1080`）或正则的 scheme 分组捕获到了协议，则按捕获到的协议导入，**不受**默认协议标签影响。

## 请求设置：方法、超时、并发、重试与出口

### 请求头

每行一个，支持两种格式，`#` 开头的行为注释：

```text
Content-Type: application/json
Authorization=Bearer some-token
# User-Agent: 也可以用等号
```

常用于需要登录态或防爬校验的站点：

```text
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Referer: https://example.com/list
Cookie: session=abc123
```

### 请求体（POST）

支持 `{page}`、`{size}` 占位符：

```json
{"page": {page}, "limit": {size}}
```

或表单格式：

```text
page={page}&per_page={size}
```

（表单格式记得配合请求头 `Content-Type: application/x-www-form-urlencoded`。）

### 并发、重试与停止

- **并发页数**：工作池大小，同时抓取的页面数。对小型站点建议保持 `1`，避免触发反爬；上限 50。
- **失败重试次数**：页面请求失败后的额外重试，重试间隔递增（第 1 次重试等 300ms，第 2 次 600ms……）。
- **失败自动停止**：失败页数累计达到该值后跳过剩余页面。`0` 表示失败也要抓完所有页。

### 抓取出口

- **本机直连**：不经过任何代理，适合目标站可直连时。
- **通过当前代理池**：使用代理池中的可用代理请求目标站，适合目标站屏蔽本机 IP 时。
- **通过指定代理**：填写固定代理地址，例如上游订阅代理。
- 本机地址（`localhost`、`127.0.0.1`、`::1`）目标会自动直连，避免代理入口自环。

### 导入后立即验证

勾选后，每条导入的代理会立刻执行一次可用性检测（受全局“请求超时”约束），结果直接写回代理池。批量导入大量代理时，验证会显著拉长任务时间，可关闭后统一用“后台检测”补测。

## 定时抓取

设置页 → “定时采集”配置组：

- **是否运行已启用的自定义抓取模板**：勾选后，调度器每次运行会依次执行所有 `启用` 状态的自定义模板（失败不影响其他模板继续运行）。
- **调度间隔**、**每日最多运行次数**、**失败后暂停分钟数** 等参数对免费源采集和自定义抓取统一生效。
- 系统概览页可查看定时采集状态、下次运行时间、今日运行次数。

## REST API 调用

所有接口需要先登录获取会话 Cookie。

```bash
# 1. 登录（保存 Cookie）
curl -c cookies.txt -X POST http://127.0.0.1:8080/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"你的密码"}'

# 2. 创建模板
curl -b cookies.txt -X POST http://127.0.0.1:8080/api/custom-scrapers \
  -H "Content-Type: application/json" \
  -d '{
    "name": "example.com",
    "enabled": true,
    "url_template": "https://example.com/list?per_page={size}&page={page}",
    "request_method": "GET",
    "page_mode": "range",
    "page_start": 1,
    "page_end": 5,
    "page_size": 100,
    "max_pages": 50,
    "concurrency": 1,
    "retry_count": 1,
    "default_scheme": "http",
    "extract_pattern": "(?P<host>(?:\\d{1,3}\\.){3}\\d{1,3})\\s*[:：]\\s*(?P<port>\\d{2,5})",
    "host_group": "host",
    "port_group": "port"
  }'

# 3. 测试提取（不保存草稿直接预览）
curl -b cookies.txt -X POST http://127.0.0.1:8080/api/custom-scrapers/preview \
  -H "Content-Type: application/json" \
  -d '{"template": {"url_template": "https://example.com/list?page={page}", "extract_pattern": "(?P<host>[\\d.]+):(?P<port>\\d+)"}}'

# 4. 运行模板（后台任务，立即返回 job_id）
curl -b cookies.txt -X POST http://127.0.0.1:8080/api/custom-scrapers/1/run \
  -H "Content-Type: application/json" \
  -d '{"mode": "direct", "check": true}'

# 5. 查询任务进度（与采集任务共用 jobs 接口）
curl -b cookies.txt http://127.0.0.1:8080/api/collector/jobs/<JOB_ID>

# 6. 停止任务
curl -b cookies.txt -X POST http://127.0.0.1:8080/api/collector/jobs/<JOB_ID>/stop
```

接口汇总：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/custom-scrapers` | 模板列表（支持 `page`/`page_size` 分页） |
| POST | `/api/custom-scrapers` | 创建模板 |
| GET | `/api/custom-scrapers/sample` | 获取内置示例模板 |
| POST | `/api/custom-scrapers/preview` | 测试未保存的模板草稿 |
| GET | `/api/custom-scrapers/{id}` | 读取单个模板 |
| PUT | `/api/custom-scrapers/{id}` | 更新模板 |
| DELETE | `/api/custom-scrapers/{id}` | 删除模板 |
| POST | `/api/custom-scrapers/{id}/preview` | 测试已保存模板 |
| POST | `/api/custom-scrapers/{id}/run` | 运行模板，返回 `job_id` |

`run` 请求体（可全部省略，省略时使用全局设置）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mode` | string | `direct` / `pool` / `specific`，抓取出口 |
| `specific_proxy` | string | `mode=specific` 时的代理地址 |
| `check` | bool | 导入后是否立即验证 |

模板 JSON 字段与 UI 表单一一对应，完整定义见 `internal/proxypool/types.go` 中的 `CustomScraperTemplate`。

## 常见问题排查

**测试提取显示“匹配示例：无”**
正则没匹配到任何内容。先看过程日志中的“页面响应预览”确认响应内容是否正常（登录页？被反爬拦截？），再调整正则。可以在本地用 Go 正则测试工具（如 regex101 选择 Golang 风格）验证正则。

**自动识别页数识别出错 / 抓了太多页**
调低“最多页数”，或显式填写“页数识别正则”覆盖内置规则。正则需带 `page` 命名分组（或数字分组并在“页数识别分组”里填编号）。

**请求全部 403/429**
目标站有反爬。依次尝试：降低“并发页数”为 1、增加“失败重试次数”、在“请求头”里补 `User-Agent`/`Referer`/`Cookie`、把抓取出口换成“通过当前代理池”或“通过指定代理”。

**提取到的代理全是重复**
该站最近已抓取过，重复条目会计入“重复”统计而不会重复导入。若想复测可用代理池页的“后台检测”。

**导入后代理可用率很低**
免费代理本身可用率就低。保持“导入后立即验证”开启，让健康检测自动淘汰；同时配合“失败删除阈值”和“自动清理不可用代理”。

**Go 正则报 `error parsing regexp`**
检查是否使用了 RE2 不支持的语法（负向先行断言 `(?!...)`、回溯引用等）。见 [RE2 语法文档](https://github.com/google/re2/wiki/Syntax)。

**并发抓取把目标站打挂了**
把“并发页数”降回 1，并设置合理的“失败自动停止”阈值，做有节制的抓取。
